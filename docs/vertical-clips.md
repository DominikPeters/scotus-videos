# Vertical argument clips

The recording dashboard can create a vertical derivative after presentation planning completes. The owner enters a title and source-audio start/end times, or loads the aligned transcript and selects passage boundaries. Audio playback uses the official recording. Rendering is explicit; Codex does not select or upload clips automatically.

Each clip is independent of the full recording's stages and upload. Its immutable source plan/bundle and audio URI are captured at creation. Times are quantized to the 20 fps output clock, with a maximum interval of ten minutes per clip. This is an operational bound, not a platform-specific eligibility rule.

`cloud/presentation/renderer/vertical.html` preserves the existing root `vertical.html` layout. The small differences are the current script's quote-card initialization hook, recusal styling, and suppressing the subscription overlay for excerpts. `cloud/render/vertical.js` replays presentation state before the selected range but takes screenshots only inside it. `original.js` keeps its landscape defaults; vertical work selects a 1080×1920 viewport and verifies the corresponding output geometry. A vertical title-fit operation replaces the landscape initialization width: the case name stays on one line down to 40px, and otherwise wraps onto two balanced lines (at most 50px). Clips omit the full-case splash and conclusion. The bundle's approved annotation cards appear in a band under the bench: `vertical.html` replaces only the card-placement functions of `script.js` (when cards show and what they contain are unchanged), so the card slides down over the transcript, which pads and scrolls by the same amount and moves down only where it cannot scroll.

Video uses H.264/yuv420p at 20 fps. Only the short audio excerpt is encoded to AAC; there is no full-recording audio re-encode. Temporary frames are deleted after encoding. The finished MP4 is retained under the private `clips/<recording>/<clip>/<revision>/` Storage prefix. The dashboard issues authenticated, 15-minute signed download links directly to Cloud Storage, avoiding a PHP video proxy.

The separate `scotus-video-clips` Cloud Run job uses four CPUs, 4 GiB and a 900-second timeout, with no automatic Cloud Run retries. The controller dispatches manual requests immediately and reconciles activity on its normal tick. Job callbacks use the existing upload-role key, a clip-specific dispatch token and worker lease. The original recording's status does not change. Private upload session URLs and leases are stripped from dashboard snapshots.

Uploading is a separate explicit dashboard action and always creates an unlisted video. It uses the existing shared YouTube auth lease, credentials and resumable transport, with durable creation/session/video checkpoints. Retries cannot silently create another video after an ambiguous creation request. Clip uploads do not add the full-case playlist, full-argument timestamp comment or original landscape thumbnail. The owner can manage publication in YouTube Studio. TikTok draft saving and public posting are separate explicit dashboard actions using the cloud browser worker; see `cloud/docs/tiktok.md`. Instagram account connection is available, but clip transfer controls are not yet wired.

Deployment needs the clip worker image/job, `clip_job` and `clip_signer` in controller settings, permission to execute the job, and permission for the controller identity to sign its own expiring download URLs. Storage read access is scoped to clip outputs. Deploy `clips.php` before the updated PHP state/API files, then the dashboard modules. Builds use `cloud/Dockerfile.clips`; the existing approved case bundle supplies fonts, portraits and transcript assets. Cloud-managed transcripts remain shared with the podcast/player.

`cloud/infra/build_image.py clips` creates a curated renderer build. `cloud/infra/deploy_clips.py --project PROJECT --worker-image PINNED_CLIPS_IMAGE --controller-image PINNED_CONTROL_IMAGE` provisions the job, preserves existing controller configuration while adding the clip settings, and deploys the controller image. It starts no renders or uploads.

To check card entry, replacement, exit, text fitting and seeking into an active card, run `node cloud/tests/vertical-cards.cjs BUNDLE CASE_ID OUTPUT_DIRECTORY` against an existing downloaded presentation bundle. The check copies the bundle, adds temporary fixture cues, and writes preview PNGs without changing the source bundle or uploading media.
